## Test instructions

/Currently only applicable to ustar_cp regression and unit tests/ 

### Test dependencies

(all available on pypi)

- Python >=3.10
- matlabengine >= 24.1.2
- Pytest >= 8.3.2
- pytest-cov >=5.0.0
- pytest-progress >=1.3.0

### How to run

1. Navigate to local top level `ONEFlux` dir in terminal
2. enter `pytest` in terminal

### Regression tests (tests/regression_tests/test_ustar_cp)

These compare the Python pipeline's stdout, exit code, and output files
against reference reports produced by the original MATLAB code, for each
of the site-year folders in `tests/test_artifacts/`.

The underlying pipeline is *stochastic*: each per-year bootstrap draws
100 resamples via a Mersenne-Twister RNG. The 2021 reference reports were
generated by MATLAB with an unseeded RNG, so the exact numeric stream
cannot be reproduced. The test architecture therefore uses three
mechanisms (see `test_cases` in `test_ustar_cp.py`):

1. **Seeded RNG** — each case passes a fixed `seed`, and `launch()` uses
   `RandomState(seed + file_index)` per file. Runs are deterministic
   under the chosen seed.
2. **`ignorable_line_prefixes`** — strips incidental mid-stream log lines
   whose presence depends on RNG (`Function cpdBin aborted.` fires only
   when a particular bootstrap draw hits a degenerate bin; both sides
   reach the same outcome either way).
3. **`stochastic_patterns`** — normalises per-run-varying numbers inside
   otherwise-stable messages, e.g. `Too few selected change points:
   382/400` vs `365/400`. Both sides agree *that* the year failed; only
   the survival count differs.

A seed-sensitivity survey across the six test sites (5 seeds × all
input years) found:

| Site | Stable | Incidental abort varies | Year-level flips |
|---|---|---|---|
| CA-Cbo    | 27/27 | 0 | 0 |
| US-ARM    | 15/18 | 0 | 3 (2010, 2019, 2020 — all near pass/fail boundary) |
| US-Ne1    | 20/20 | 0 | 0 |
| US-Syv    | 21/21 | 0 | 0 |
| US-Vcm    | 15/15 | 0 | 0 |
| US_ARc    |  2/2  | 0 | 0 |

US-ARM's three marginal years hover around ~380/400 selected change
points (out of 400 required), so the historical MATLAB seed landed on
one side of the boundary while many Python seeds land on the other
side — both are statistically defensible readings of the same data.
We set `seed=1` for US-ARM because it happens to match the historical
side for all three years; other seeds still produce valid science, just
occasionally flip these three years' classification.

If you change the pipeline (e.g. fix a numerical bug in `fcBin`,
`prctile`, `nlinfit`), re-run the sensitivity experiment to update
this table and pick appropriate seeds.
